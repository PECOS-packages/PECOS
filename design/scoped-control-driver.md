# Scoped control driver for synchronous program execution

## Status

The generic driver and an opt-in scoped FFI request callback are implemented.
Native `QisEngine` execution still uses its existing staged worker: the callback
is not yet connected to that controller. No Python option or performance
improvement is claimed. See [the FFI contract](scoped-request-callback.md).

## Motivation and contract

A compiled program can require a synchronous runtime response before its next
instruction. A pull-only classical control interface can require an extra worker
and rendezvous for each such call, even when no quantum work is ready. Allow a
classical controller to run on its caller's stack and synchronously submit work to
the existing controlled engine.

`ControlEngine::run_with(input, process)` is object-safe and borrows its callback
for the invocation. Its default implementation performs exactly the existing
`start` / `NeedsProcessing` / `continue_processing` loop. Every input is forwarded,
including empty inputs. Reset, seeding and shot identity remain the caller's job.
The callback has no `Send` or `'static` requirement and cannot be retained or moved
to another thread by safe code. The generic, classical and noise-model boxes all forward overrides.

`HybridEngine` calls this hook with its disjoint `QuantumSystem::process` borrow.
Monte Carlo still owns worker scopes, clones, reseeding, reset and global shot
identity. The quantum system still runs the noise controller to completion,
including simulator measurements generated by noise and further operations
selected from those results. A controller cannot replace that path with direct
simulator calls through this interface.

The hybrid host latches the first controlled-engine error or panic. It reports callback
failure through a processing error, rejects later callback attempts without executing
them, and returns the original typed error or resumes the original panic payload
when the controller returns. A controller's own panic propagates normally. This
preserves the existing outer shot guard and reset policy; no new cross-shot retry
policy is introduced. Standalone callers of `run_with` supply their own callback
and remain responsible for its failure policy.

The generic `EngineSystem::process_as_system` default and direct staged callers
remain staged. `HybridEngine` already overrides that method through `run_shot`,
so its public entry points consistently reach the new hook.

## Why not skip empty requests

An arbitrary noise model or quantum engine can change state, consume RNG, return
an outcome or fail on an empty input. Therefore empty stages are not globally
elidable. Scheduled consumers have a narrower exact-empty wait contract, but only
after validating shot context, poison state and backend capacity. A zero-gate timed
batch or custom-only event batch is not an empty wait. This change does not filter
messages or alter the inner noise-controller loop.

## Native QIS follow-up gates

A future opt-in native implementation may run the compiled program on the existing
Monte Carlo worker and service its runtime requests synchronously. The callback
must still drain runtime-owned work and deliver feedback before acknowledging a
request. Reuse staged request lowering, force-once/result lookup, tracing,
measurement identity and terminal delivery. Retain staged execution as a fallback.

Before enabling that path:

- Register a scoped callback in the exact loaded FFI library, bound to a live
  execution context. Remove registration on success, error and unwinding; clones
  must never retain a live callback or its userdata.
- Release context locks and TLS borrows before entering the host callback. Reject
  callback reentry and nested program entry before accessing borrowed state.
- Catch Rust panics at the C ABI trampoline and preserve original host failures.
  Return a plain status before any destructor-free transfer to the C recovery
  guard. `catch_unwind` cannot make a `longjmp` across live Rust frames safe.
- Preserve cancellation checkpoints and explain the mode's limits: same-thread
  execution cannot detach an unresponsive native program as the staged worker can.
  Select the mode before the shot; do not silently change timeout guarantees.
- Prove parity for runtime scheduling/idling, gate-only batches, forced Boolean
  and integer/leakage futures, measurement-dependent batches, noise-generated
  measurements, custom calls, decoding, terminal output and immediate failures.
- Test public fixtures through MonteCarlo/Hybrid/QuantumSystem, including worker
  scope, shot/RNG identity, reset/reuse, both error and panic recovery, and ordered
  emissions. Compare exact old outputs before measuring uninstrumented throughput.

A stackful coroutine would preserve the pull interface but adds stack-switching,
platform and recovery-guard ownership concerns. Moving only the runtime into the
program worker still needs cross-thread processing for every emitted batch. The
scoped driver is the smaller prerequisite for avoiding those crossings while
retaining the ordinary engine composition.
