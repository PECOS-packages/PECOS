## Contract and oracle

The central roster contains 37 simulator declarations. Phase-exact representations compare the full output state, including global phase, against the matrices returned by `Clifford::canonical_1q_matrix` and `GateType::canonical_1q_matrix`. Projective representations compare `G P G†`, including sign, for `P ∈ {X,Y,Z}`. Density matrices stay projective because `ρ → UρU†` cancels a scalar phase on `U` identically.

Coverage is enumerated by `Clifford::all_1q` and `NAMED_SINGLE_QUBIT_GATES`; each roster capability is enforced with a compile-time gate-trait bound. There are no runtime string-based gate skips.

Tolerances: CPU f64 state vector `1e-12`; f32 state vector `2e-5`; GPU f64 and reconstructed stabilizer/MPS amplitudes `1e-10`; projective density f64 `1e-10`, f32 `2e-5`. The f64 state-vector threshold is comfortably above machine epsilon for these short circuits, reconstructed/GPU f64 allows readback and normalization work, and f32 allows a short shader/SIMD sequence without admitting a gate-scale error.

`CircuitRunner`, `CoinToss`, `CustomScoreCriterion`, `GateSystemRegistry`, and `ThresholdCriterion` are excluded as runner/sampling/scoring/registry utilities, not quantum-state or Pauli representations. `ForeignSimulator` is excluded because it delegates to a concrete simulator whose declaration owns the tier.

## Root-cause assessment

- **SparseStateVecAoS (1):** the uninterrupted four-qubit probe reproduces [#613](https://github.com/PECOS-packages/PECOS/issues/613): seven expected nonzero amplitudes become zero after the multi-target H5 slice and downstream CX. It is not projectively equivalent to the oracle state.
- **StabMps and Mast (35 each):** every failed state is the intended canonical action multiplied by a root-of-unity phase. Their identical failure sets and factors match the shared amplitude-read reconstruction defect in [#614](https://github.com/PECOS-packages/PECOS/issues/614).
- **StabMpsCompile (39):** 35 Clifford failures match the same phase-reconstruction pattern used to materialize its tableau. Its four T/Tdg rows are separate: the materialized action simplifies to identity because compile mode records non-Clifford resource information but retains no amplitude state for those rotations.
- **StabVecGeneric (27):** every row remains projectively equal to the intended action, with only ±1 or eighth-root phases. This looks like one phase-bookkeeping/reconstruction family, but it uses a different read path from #614 and should not be assumed to be the same implementation defect.
- **DensityMatrix (36):** all failures are consistent with one Choi-half ordering error: the observed action is `U* P Uᵀ` where `U P U†` is required. Real gates therefore pass; gates whose canonical matrices contain imaginary entries expose sign/dagger reversals. The state extractor interprets the high half as the density row while the gate path labels/applies the low half as the system, which is the likely owning-layer mismatch.
- **BitmaskPauliProp (72):** all Pauli axes are projectively correct, but the representation discards the sign, so every required signed-conjugation check can report only `±X`, `±Y`, or `±Z`. This is one representation-capability root cause, not 72 axis-kernel defects.
- **SymbolicSparseStab and SymbolicSparseStabVecSet (1 each):** both expose inherent gate methods but implement no gate trait beyond `QuantumSimulator`. Trait-bound-driven coverage is therefore impossible without a production trait implementation; the two structural failures share that root cause.
